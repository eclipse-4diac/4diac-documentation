= I/O Configuration for Different Platforms
:lang: en

Eclipse 4diac uses I/O function blocks such as `IX`, `QX`, `IW`, and `QW` to access the inputs and outputs of supported hardware. 
Applications use these function blocks independently of the physical I/O channels. The hardware configuration and I/O assignments are defined separately.


== I/O Configuration and Assignment

The hardware configuration is modeled using one or more hardware-specific function blocks in an IEC 61499 resource. 
For modular hardware, these function blocks can represent the controller and its expansion modules. 
The corresponding function block types are available in the `io` folder of the type library.

Application I/O function block instances are assigned to physical I/O channels through `STRING` inputs on the hardware configuration function blocks. 
Each input specifies the dot-separated hierarchical name of the corresponding instance: the application name, any enclosing subapplication or composite function block instance names, and finally the I/O function block instance name.
If the `PARAMS` input of the I/O function block is set, its value is used as the name instead.

For example, `MachineControl.Conveyor.MotorEnable` identifies the `MotorEnable` I/O function block inside `Conveyor` in the `MachineControl` application.

== Previously Supported Hardware

The following hardware I/O modules were removed with 4diac FORTE 3.4 because they had not been ported to the current I/O interface:

* CONMELEON C1 (`FORTE_MODULE_CONMELEON_C1`)
* Linux I²C GPIO devices (`FORTE_MODULE_I2C_Dev`)
* LEGO MINDSTORMS EV3 (`FORTE_MODULE_LMS_EV3`)
* Bosch Rexroth PLCs (MLPI) (`FORTE_MODULE_MLPI`)
* ODROID (`FORTE_MODULE_Odroid`)
* PiFace (`FORTE_MODULE_PiFace`)
* Raspberry-SPS (`FORTE_MODULE_Raspberry_SPS`)
* MicroControl µMIC.200 (`FORTE_MODULE_uMIC`)

[TIP]
.Interested in restoring support for one of these platforms?
====
We welcome contributions to port these modules to the current I/O interface.
See https://github.com/eclipse-4diac/4diac-forte/issues/1136[GitHub issue #1136]
for details and coordination.
====
